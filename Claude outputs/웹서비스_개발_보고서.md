# 부동산 PF 사업성 분석 웹 서비스 개발 보고서

담당 범위  웹 서비스 구축 · 백엔드 · 배포
작성 기준  2026년 10월 27일

필지를 고르면 토지·건축물·용도지역 정보를 모으고, 토지 실거래와 청약홈 분양 사례로 사업 수지와 월별 현금흐름을 계산하는 웹 서비스를 구축하였다. 예상 토지매입대금은 팀원의 토지 단가 예측 모델이 낸 6개월 뒤 그룹 단가에 필지 면적을 곱해 구한다.

## 전체 구성

![서비스 구성도](서비스_구성도.png)

| 구분 | 사용 기술 |
| --- | --- |
| 서버 | Python, FastAPI, Uvicorn |
| DB | MySQL 8.4 (Docker) |
| 공간 계산 | Shapely, pyproj |
| 예측 모델 | scikit-learn 선형회귀 (CatBoost 23번으로 전환 가능) |
| 화면 | React, Recharts |
| 배포 | AWS EC2 (Ubuntu) |

## 주요 기능

| 기능 | 내용 |
| --- | --- |
| 자료 적재 | 토지 실거래(약 764만 건)·청약홈 분양정보를 MySQL에 적재. 매일 새벽 3시 최근 3개월 자동 갱신 |
| 입지 조사 | 브이월드·도로명주소로 필지·건축물 조회, 필지 경계와 용도지역 경계를 겹쳐 면적 배분 |
| 비교사례 | 토지 실거래를 지목 6 × 용도지역 8 = 48그룹으로 분류, 최근 60개월 사례 선정 |
| 사업성 계산 | 개발 규모 → 분양 수입 → 토지비 → 사업비 → 현금흐름 → 목표 지표 |
| 분석 저장 | 화면이 보낸 결과 대신 서버가 다시 계산해 저장 (값 조작 방지) |

## 예측 모델 연계

사용자는 필지만 고르므로 모델 입력 13개(숫자 12개 + 토지 그룹)는 서버가 만든다. 입력월은 기준월 − 2개월, 예측 대상월은 기준월 + 6개월이며, 없는 값은 채우지 않고 '자료 없음'으로 처리한다. 팀원 표본 6,000건과 입력값이 모두 일치하였다.

예상 토지매입대금 = Σ(필지별 그룹 예측 단가 × 면적). 예측하지 못한 필지는 예측한 필지들의 평균 단가로 채우고, 모델이 꺼져 있으면 비교사례 금액을 쓴다.

2026년 10월 27일 선형회귀 모델로 바꾸었다. 팀원 모델과 같은 단가가 나오는 것을 확인하였고, 기본 예시(안산 장상동 27필지)의 예상 토지매입대금은 200.91억 원에서 233.82억 원이 되었다.

## 성능 개선

| 문제 | 원인 | 조치 | 결과 |
| --- | --- | --- | --- |
| 동시 접속 시 연결 거부 | 요청마다 19MB 화면 생성 → 메모리 부족으로 서버 종료 | 화면을 한 번 만들어 재사용, 압축 전송 | 50명 동시 접속 최대 628MB. 전송량 19MB → 2.9MB |
| 비교사례 조회 지연 | 실거래 약 764만 건 전체 탐색 | 인덱스 추가 스크립트 작성 | 한 달 조회 3.7초 → 6ms |
| 사용자 없을 때도 메모리 유지 | 동시 계산 때 늘어난 메모리를 돌려주지 않음 | 실행 설정 `MALLOC_ARENA_MAX=2` | 915MB → 791MB |

## 테스트

자동 테스트 246건(서버 194건, 화면 52건)이 모두 통과한다.

## 배포

앱 서버(AWS EC2)에서 FastAPI 서버를 4175 포트로 실행하고, DB는 별도 서버의 Docker MySQL을 쓴다. 코드는 `git pull` 후 서버를 재시작해 반영하고, 모델은 `.env`의 `MODEL_ENTRYPOINT` 한 줄로 바꾼다.
