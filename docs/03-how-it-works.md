# 3. 요청 하나가 처리되는 과정

구조를 알았으니, 실제로 버튼을 눌렀을 때 어떤 일이 일어나는지 세 가지 사례로 봅니다. 각 단계의 `[ ]` 안은 담당 파일입니다.

## 사례 ① 필지 정보 조회

사용자가 지도에서 땅을 클릭합니다.

```
브라우저  ──"이 땅 정보 주세요"──►
 [main.py guard] 접속 주소 검사 통과
 [public_data.py] "동시 조회 4건 초과 아닌가?" 확인
 [domain]         브이월드에 인증 키를 붙여 질의 (키는 서버 안에서만 사용)
 [domain]         받은 자료에 건축물·공시지가 등 추가 정보를 덧붙임
 [web.py ok()]   응답에 키가 섞이지 않았는지 마지막 확인 → 브라우저로 전달
```

핵심: **브라우저는 정부 사이트와 직접 대화하지 않습니다.** 항상 이 서버가 대신 묻고, 키는 서버만 알고 있습니다.

## 사례 ② 분석 저장

사용자가 분석을 마치고 "저장"을 누릅니다.

```
브라우저  ──"이 분석 저장해 주세요"──►
 [web.py json_body] 올바른 JSON 형식인지, 64MB 이하인지 검사
 [snapshots.py]  ① 비밀번호·키가 들어 있지 않은지 검사
                 ② 화면이 계산한 숫자는 버리고, 계산 엔진으로 처음부터 다시 계산
                 ③ 실시간 조회로만 얻는 자료(분양 사례 등)는 저장본에서 제외
                 ④ 번호(id) 중복이 없는지 확인
 [snapshots.py]  MySQL의 analysis_snapshots 테이블에 기록
 [web.py ok()]   저장된 번호를 응답
```

핵심: **저장은 기록이 아니라 검증입니다.** 화면에서 숫자를 바꿔 보내도 서버가 다시 계산하므로 조작된 값이 저장되지 않습니다.

> 참고: 예전에는 저장하면 내 PC에 `V6.html` 파일이 생겼습니다. 지금은 파일을 만들지 않고, 화면을 열 때마다 데이터베이스에서 읽어 만듭니다.

## 사례 ③ 학습 모델 예측 (앞으로)

학습 모델이 준비된 뒤의 흐름입니다.

```
브라우저  ──"이 조건으로 예측해 주세요"──►
 [model.py]      입력 형식 검사
 [model.py]      모델이 준비되어 있는지 확인
                 · 없음 → "모델이 아직 준비되지 않았습니다" (503) 로 정중히 거절
                 · 있음 → 모델에게 전달
 [data/models/]  모델이 계산해서 결과 반환
 [model.py]      모델 이름·버전과 함께 응답
```

**지금은 모델이 없으므로** 이 요청은 항상 "준비되지 않음"으로 답합니다. 하지만 이것은 고장이 아니라 정상 동작이며, 나머지 기능에는 영향이 없습니다.

## 화면을 처음 열 때

주소창에 접속하면 서버가 **샘플 선반**의 자료(기본 샘플 포함)를 데이터베이스에서 읽어 화면에 끼워 넣어서 보내 줍니다. 그래서 정부 API 키가 없어도 저장된 예시(안산 장상동 27필지)는 바로 볼 수 있습니다. 새로 조회하는 기능만 키가 필요합니다.

## 문제가 생기면 어떻게 보이나

어떤 단계에서 실패하든 `main.py`의 guard가 받아서 `web.py`의 `error_response()`로 항상 같은 모양의 안내를 보냅니다.

| 상황 | 사용자에게 보이는 결과 |
|---|---|
| 입력이 잘못됨 | "입력 오류" + 이유 (400) |
| 저장된 분석을 못 찾음 | "찾을 수 없음" (404) |
| 정부 사이트 조회가 몰림 | "잠시 후 다시 시도" (429) |
| 모델이 없음 | "학습 모델이 아직 준비되지 않았습니다" (503) |
| 서버 내부 문제 | 일반 안내문만 표시. 기술적 세부 내용·키는 노출하지 않음 (500) |
