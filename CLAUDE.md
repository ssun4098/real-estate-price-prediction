# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

개발사업성 분석 V6: a real-estate development feasibility tool. A prebuilt React dashboard (`frontend/build/V6.template.html`) talks to a Python backend that calls Korean public APIs (VWorld, data.go.kr, Juso, KOSIS, SGIS) and runs the financial analysis engine. UI text, errors and comments are mostly Korean; keep that.

## Running

There is one server: the FastAPI app, the `server/` package (the old stdlib server `V6.py`/`pf_server.py` was removed). All Python lives in `server/`; `server/domain/` is the calculation/public-API layer.

## Commands

```sh
cp .env.example .env                # MYSQL_* = the user's EXISTING MySQL container, plus API keys
docker compose up -d --build        # api only → http://127.0.0.1:4175/
python -m server                    # same server without Docker (loads .env, 127.0.0.1:PUBLIC_PORT)
docker compose --profile deploy up -d --build   # server: also starts nginx `proxy` on 80 (HTTP) and 443 (HTTPS) → api; `certgen` makes a self-signed cert in ./certs/ if none exists; config in deploy/nginx.conf (app port 4175 hard-coded there on purpose; don't template it) (see docs/04). Only ports 80 and 443 are meant to be open; the app (4175) and MySQL stay internal.

# Tests (unittest, no network/keys/MySQL). Interpreter needs requirements.txt installed.
python tests/run_tests.py
python -m unittest test_engine        # one file, from the project root with PYTHONPATH=.;tests (Windows) / .:tests
```

`tests/test_app_api.py`, `tests/test_app_storage.py`, `tests/test_land_trade_table.py`, `tests/test_applyhome_table.py` and `tests/test_daily_load.py` exercise `server/` against SQLite via `DATABASE_URL`. There is no linter config. Frontend (`frontend/`): `build/V6.template.html` was produced by the Data app plugin build (prebuilt runtime script + a separate base64 content script), not by `npm run build` (vite output differs and would replace the runtime). After editing `frontend/src/content/`, run `npm ci` then `node build-content-template.mjs` in `frontend/`: it re-bundles only `src/content` (rolldown, CJS, runtime modules external) and swaps it into the template's content script; content CSS changes are NOT picked up (reuse existing classes). Its `AGENTS.md` and `protected-runtime.json` mark protected runtime files that must not be edited without the authorize script — don't touch the frontend unless asked.

## Architecture of `server/`

`server/README.md` is the human-facing code map (Spring analogies, how to add a feature); keep it in sync when files move.

Organised **by feature**, so one feature reads top to bottom in one file. The user found the previous strict layering (api/services/repositories/db/core/container, ~35 files) too hard to follow; don't reintroduce per-layer packages.

- `main.py` — `create_app()`: lifespan builds everything (DB → `Collector` + land store (`LandTradeTable` or `MySqlLandStore`) → feature objects) and stores it on `app.state`; registers the `guard` middleware and the routers. Run with `uvicorn server.main:create_app --factory` (no module-level `app`).
- `settings.py` — `Settings.from_env()`. `env.py` — `.env` loader and API-key validation. `web.py` — shared HTTP rules. `db.py` — ORM tables, `connect()`, `db_errors()`.
- `features/<name>.py` — each file: routes at the top (`router = APIRouter()`), then the rules/DB code (`SnapshotService`, `PortfolioService`, `PublicData`, `ModelHolder`). Routes reach their object via `request.app.state.<name>`. A new feature = a new file here + one line in `main.py`.
- Imports are absolute from the project root (`from server.domain.analysis import analyze`); there is no `sys.path` manipulation. Dependency direction is one way: `features → domain`; `domain` never imports `features`, FastAPI or SQLAlchemy.
- Errors: the `guard` middleware in `main.py` catches every exception and returns `web.error_response(exc)` → `{"error":{"code","message"}}` (`ValueError/KeyError/TypeError` → 400, `ApiError` keeps its status, other → 500 with a generic message, nothing logged). FastAPI's own 404/405/validation errors are mapped by registered exception handlers. Handlers return `ok(data)` (`SafeJSONResponse`), not dicts, to avoid re-serialising up-to-64MB documents; every response body is refused if it contains a configured API key or the DB password.
- Request bodies are parsed by the `json_body` dependency (JSON content type, 64MB cap, NaN rejected). There is no Host allow-list (the user removed `ALLOWED_HOSTS` on purpose; don't reintroduce it). `check_origin` only rejects cross-site requests: `Sec-Fetch-Site: cross-site`, or an Origin that is not `http://`/`https://` + the request's own Host.
- Access logging is disabled on purpose (URLs carry addresses and upstream keys).

### Storage

The app does **not** run its own MySQL: it connects to a MySQL 8.4 container the user already runs on their PC (it also holds their own land-trade data). In Docker the api joins the external network `v6_mysql` (`MYSQL_NETWORK`) and reaches the container by name (`MYSQL_CONTAINER`, default `land-mysql`) on port 3306; the user connects it once with `docker network connect v6_mysql land-mysql`. Directly (`python -m server`), via `MYSQL_HOST`/`MYSQL_PORT`. `db.connect` only creates missing app tables, never alters/drops existing ones, and refuses to start if a same-named table lacks expected columns. Never add code that drops, truncates or migrates tables it did not create.

Land trades: by default (`LAND_TRADE_SOURCE=table`) `Collector` reads the user's own bulk-loaded tables via `features/land_trade_table.LandTradeTable` (set as `collector.land_store` with `collector.land_source="table"`): `land_trade` (one row per deal, `lawd_cd`+`deal_ym`) and `land_trade_job` (a month counts only if `loaded_rows >= total_count`; missing months raise `LAND_NOT_LOADED`, never treated as zero). No public-API call is made for land in this mode. Row verdicts reuse `public_api.land_trade_row()` so DB and API paths judge identically; row ids mimic API paging (100/page). Request handling only reads these tables; the only writer is the daily loader. A daily loader (`features/daily_load.DailyLoader`, started in `main.py` lifespan as a daemon thread; `DAILY_LOAD=on|off`, `DAILY_LOAD_TIME=HH:MM` KST, `DAILY_LOAD_MONTHS`) refreshes these tables: last N completed months × sgg codes found in `land_trade_job` (DELETE+INSERT per month, `REPLACE` job row, failures to `land_trade_fail`), then full Applyhome notices/models via `REPLACE` (failures to `applyhome_fail`). It mirrors the user's original loaders (`land_trade.py`/`applyhome.py` in their separate land_trade folder), calls the API through `Collector.request` (not `odcloud`/`_land_page`, which are diverted to the tables), stops on auth/quota errors, redacts secrets in stored errors, and takes a MySQL `GET_LOCK`. Status `GET /api/daily-load`, manual `POST /api/daily-load/run`. `LAND_TRADE_SOURCE=api` restores the old API + `MySqlLandStore` cache path.

청약홈 (Applyhome) notices/models: by default (`APPLYHOME_SOURCE=table`) `collector.applyhome_table = ApplyhomeTable(sessions)` (`features/applyhome_table.py`), and `Collector.odcloud()` / `_coverage_count()` query `applyhome_apt_notice` / `applyhome_apt_model` instead of the API, returning rows with the API's uppercase field names (columns first, then keys from the `extra` JSON). Only the condition keys the app uses are supported (`HOUSE_SECD/HOUSE_DTL_SECD::EQ`, `RCRIT_PBLANC_DE::GTE/LTE/LT`, `HSSPLY_ADRES::LIKE`, `HOUSE_MANAGE_NO/PBLANC_NO::EQ`); unknown ones raise. Read-only for requests (the daily loader refreshes them); geocoding still uses VWorld. `APPLYHOME_SOURCE=api` restores API calls.

App tables (`server/db.py`) hold documents as LONGTEXT JSON strings (preserves key order/numbers): `analysis_snapshots`, `portfolio_samples`, `app_settings`, and the land-trade cache (`land_complete/pages/errors`). Table/column names must stay stable (existing data). `MySqlLandStore` (`features/land_store_mysql.py`) subclasses `domain/land_store.LandStore` (SQLite) and keeps its interface/cache policy so `Collector` is unchanged. Bundled read-only samples come from `data/samples/` (`default.json` names the default). `V6.html` is no longer written to disk; `features/pages.py` renders it per request.

### Services worth knowing

- `SnapshotService.recompute` never trusts client-computed results: it re-runs `validate_snapshot` + `export_snapshot`, and rejects any payload containing a configured secret.
- `PortfolioService` samples are frozen captures (`persistencePolicy=portfolio_frozen_v1`); reading one must not recompute it with the current engine. The default sample is an explicit pointer and is never silently replaced.
- `PublicData.slot()` allows at most 4 concurrent upstream lookups through `domain.public_api.Collector` (429 `BUSY` otherwise).

### Trained model

`features/model.py` defines the `Predictor` protocol and `ModelHolder`, which loads `MODEL_ENTRYPOINT=module:Class` from `MODEL_DIR` (`./data/models`, mounted read-only). With no entrypoint the app starts normally, `/api/model/status` reports `not_configured`, and `/api/model/predict` returns 503 `MODEL_NOT_READY`. Model failures at load never block startup. Details in `data/models/README.md`. The analysis engine does not depend on the model.

The current model is the teammate's CatBoost #23 (handoff package `개발자전달_CatBoost23_20261027`): `data/models/land_price_model.py` (`MODEL_ENTRYPOINT=land_price_model:LandPricePredictor`) loads `model.cbm` (~110MB, git-ignored, copied by hand; `catboost==1.2.10`) and the tracked `model_info.json` (features, 5,085 `training_groups`, log1p target); `load` refuses if code/info/model feature lists differ. It predicts the 6-months-ahead monthly median unit price (KRW/m², `expm1`, clipped at 0) of a group `"sgg|jimok_group|zone_group"` (jimok 대/전/답/임야/공장용지 else 기타; zone via the teammate's exact raw-name table `ZONE_TABLE` into 8 groups incl. 비도시지역 and `용도미지정 등`; unknown raw zone names raise, never guessed). `data/models/land_price_inputs.py` builds the 12 numeric inputs from tracked `data/models/inputs/` (group monthly history, region map, regional macro, COFIX release history; regenerated from a handoff package with `inputs/make_inputs.py`, pandas+pyarrow only there) using the teammate's `tools/build_context.py` rules: feature month = forecast month − 2, target = +6, COFIX = latest released by forecast-month end, exact-month joins only — no imputation; missing → `InputsMissing` → `LookupError` → 409 `MODEL_DATA_MISSING`. Latest forecast month is limited by macro (to 2026-07) and COFIX releases (to 2026-08) → 2026-08; `build_latest` looks back up to 6 forecast months per group, so target months can differ per group (shown to users). Verified: 6,000 teammate samples match all 12 features; the 5 example predictions match. `POST /api/model/land-estimate` (in `features/model.py`) prices parcels (pnu[:5] = sgg, raw jimok, raw zone, area) per group and returns rows + `totalWon` (only if all priced) / `partialWon`. **The model now sets the land purchase amount used everywhere.** `analyze(inputs, partial, land_model=None)` / `validate_snapshot(..., land_model)` / `persistence.export_snapshot(..., land_model)` take `land_model` = `ModelHolder.estimator()` (= `ModelHolder.land_estimate`, or None when the model isn't ready); `/api/analyze`, `SnapshotService` and `PortfolioService` pass it (domain never imports features). `domain/analysis/land_price._apply_land_model` (run right after `_land`, before `_apply_finance_price`) sets `land.representativeWon` = Σ(model unit × area for priced parcels) + (area-weighted average model unit × area of unpriced/unclassifiable parcels) × landAdjustmentPct factor — the user chose 'fill with model average'. It keeps `comparablesRepresentativeWon`, sets `amountBasis` ('model'|'comparables') and `modelEstimate` (rows with `basis` 모델 예측/평균 단가로 채움, counts, average, targetMonths). Falls back to comparables when the model is off, raises, prices no parcel, or a parcel has no area. The frontend mirrors it exactly in `model-land-estimate.mjs` (`modelParcels`, `combineLandModel`, `applyLandModel` re-applies the last server `modelEstimate` per-parcel units during previews/sanitize: `revision-model.projectRevision`, `v2-policy.sanitizeSnapshot`) so preview == server. The '예상 토지매입대금' box (`LandDistribution.jsx` `V5LandPlot` → `ModelLandEstimate`, no fetch) shows `land.modelEstimate`; when there is no model value (frozen sample, model off) it shows the comparables amount the table actually uses, and when the land row is not 모델% 100 (or a typed amount) it adds a '수지분석 적용액' line — so the box never silently disagrees with the table (`landAmountStatus.appliedPct`); comparables box plot/dropdown were removed there (`UnitPriceBox`/`FallbackPrice` kept unused). The 수지분석 land row shows '모델%' and a model note (`landAmountStatus.modelUsed/modelSummary`); the 토지 면적·단가 panel is labelled as comparables detail. Frozen samples have no `modelEstimate` until recalculated. Tests: `tests/test_land_price_model.py` (model parts skip without catboost or `model.cbm`).

## `server/domain/`

Calculation and public-API modules (formerly `backend/pf_*.py`; renamed, contents unchanged): `analysis/` (the calculation engine, split by topic from the old 1,500-line `engine.py` with function bodies unchanged: `engine` = `analyze`/`validate_snapshot` orchestration, `development`, `comparables`, `revenue`, `land_price`, `costs`, `cashflow`, `common`; import `analyze`/`validate_snapshot` from the package, private helpers from their module), `public_api` (`Collector`: all upstream HTTP, caches, comparables; `ApiError` — intentionally kept as one class; the user decided not to split it by agency), `survey` (site survey, parcel enrichment), `land`/`boundary`/`regions` (land classification, parcel boundary allocation, region catalog), `persistence` (export rules), `land_store` (SQLite land cache; base class of `MySqlLandStore`), `geometry` (lazy shapely/pyproj import). Standard library plus shapely/pyproj only — do not add dependencies here. Export policy: Geocoder-derived/real-time revenue data is stripped from saved snapshots and must be re-queried (`exportPolicy: v5-geocoder-requery`).

Land comparison groups (`land.py`, mirrored exactly in `frontend/src/content/dashboard/land-classification.mjs` + `land-comparison.mjs`; keep both in sync, `RULES_VERSION`/`LAND_RULE_VERSION` = `land-match-v7-48-groups-1`): 용도지역 8 groups × 지목 6 groups, from the team doc '토지실거래가 데이터 전처리 개선 내용' (same as the CatBoost model). Zone groups come from the zone code via `ZONE_GROUP_OF_CODE` (전용주거/일반주거/준주거/상업/공업/녹지지역, 관리·농림·자연환경보전 → 비도시지역); UQA100 bare 주거지역 is unclassifiable. Transactions only: 용도미지정·개발제한구역·기타 → `용도미지정 등` (status ready) and blank zone → `용도미지정 등` (missing); on parcels 개발제한구역 is an overlay (용도구역), never a zone. 지목: 전/답/임야/대/공장용지 kept, all others and blank → 기타. Saved boundary allocations may carry old `zoneMatchKey` values; the frontend validator recomputes the group from the zone code instead of trusting the stored key. Frozen portfolio samples keep their saved (old 12-group) results until the user recalculates.

## Configuration

All config is environment variables (see `.env.example`); in Docker they come from `.env` via compose, with `python -m server` from `env.load_environment`. That loader rejects unknown names, so any new variable must be added to `env.APP_NAMES`. `server/settings.py` reads them. VWorld keys must match `VWORLD_DOMAIN`.
